# D-P2-20261124T044034Z-0 (pre-session; for the human to copy to prereg/deviations/ and commit before the GPU session)
- UTC: 2026-11-24T04:40:34Z (written by Claude before any P2 GPU data; the human commits it before starting the session)
- Step: how the session's files are copied off the instance (prereg section 1, "Deviation files and the session log are copied off the instance after every deviation, after the pilot projection, after every model and at the hard stop (SYNC_DEST/_session_<UTC>/, rsync --mkpath, rsync >= 3.2.3)").
- What is done instead:
  - `SYNC_DEST` is a directory on the VM, inside a second clone of the repository (`~/depth-law-sync/p2_syncdest`). The driver's rsync copies (deviations, the log, run dirs) land there at each event, exactly as frozen.
  - The off-instance step is `scripts/p2_push_loop.sh`, which commits that clone and pushes it to the GitHub branch `p2-gpu-session` every 60 s. It also copies results/P2, results/P2smoke, results/logs and deviations_pending from the run checkout.
  - The run checkout stays at the frozen commit (tag prereg-P2).
- Reason: a rented VM cannot rsync to the human's computer (no inbound SSH), so GitHub is the off-instance store.
- Effect:
  - off-instance copies lag each event by at most about 60 s;
  - at the budget hard stop (shutdown), the last minute may reach GitHub only after the instance is resumed and the loop is run once.
  - No measurement, rule or analysis step changes.
- Check: `scripts/p2_verify_sync.py` on a checkout of `p2-gpu-session` verifies every file listed in VM_FILES.sha256 (written on the VM at the end) by sha256 before the VM is destroyed.
